# Prototype V0.4 实施基线

## 本版本必须实现

### 初始状态

- 皇帝：20岁
- 四大势力满意度：全部100
- 五州：北朔、河东、中州、江南、岭南
- 国家资源：国库、粮食、兵器、军队、皇权、民心

### 四大势力

```text
士族 / 武将 / 百姓 / 豪强
```

满意度是王朝存亡的核心指标，必须在 UI 中高优先级展示。

### 主城建筑

六座独立建筑：

```text
官仓
国库
兵营
武库
工部作坊
市舶司
```

每座建筑独立 Lv.1～Lv.5，可分别建设、升级、产生月度产出并承担维护成本。

### 粮食循环

```text
月度州粮食生产
      ↓
中央粮食收入
      ↓
建筑粮食产出
      ↓
军队粮耗
      ↓
兵营粮耗
      ↓
粮食是否不足？
```

军队：

```text
每名士兵每月消耗 0.05 粮食
```

兵营：

```text
每级兵营每月消耗 300 粮食
```

### 粮荒

如果粮食不足：

- 粮食归零
- 损失部分农民
- 损失部分士兵
- 百姓满意度下降
- 武将满意度下降
- 州民心下降
- 叛乱风险上升

粮荒必须能够在历史日志中解释清楚。

## UI 验收

首页必须让玩家第一眼看到：

1. 四大势力满意度
2. 当前最低满意度
3. 王朝危机压力
4. 粮食库存与月度粮食变化
5. 六座主城建筑及等级

四大势力不能作为普通的低优先级信息卡隐藏在页面末端。

## Engine 验收

- `GameState.BUILDING_IDS` 与 `data/buildings.json` 完全一致
- `GameState.FACTION_IDS` 与 `data/factions.json` 完全一致
- `seedData.ts` 不修改势力 / 州 / 国家初始值
- `FoodSystem.ts` 统一处理粮荒后果
- `GameEngine.advanceMonth` 必须经过粮荒结算
- UI 不直接修改 GameState

## 人工测试

### Test 1：正常开局

新游戏检查：

```text
士族 100
武将 100
百姓 100
豪强 100
```

### Test 2：建设

依次建设六座建筑，确认：

- 每座都可以独立升级
- 升级成本随等级增加
- 月度产出随等级增加
- 维护随等级增加

### Test 3：扩军粮耗

提高军队人数，进入下个月，确认粮食月耗增加。

### Test 4：兵营粮耗

连续升级兵营，进入下个月，确认粮食月耗增加。

### Test 5：粮荒

使用测试数据人为制造：

```text
food = 0
army = 高值
barracks = 高等级
```

进入下个月，确认：

- 农民减少
- 士兵减少
- 百姓满意度降低
- 武将满意度降低
- 州民心降低
- 叛乱风险提高
- 历史日志出现粮荒说明

### Test 6：势力危机

人为降低任意势力满意度，确认 UI 的危机压力同步升高。
