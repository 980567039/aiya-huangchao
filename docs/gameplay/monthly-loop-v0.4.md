# 《哎呀，朕的皇朝怎么又亡啦》月度游戏循环 V0.4

> 版本：V0.4
> 日期：2026-08-26
> 状态：核心模拟循环设计基线

## 1. 目标

把前面的“资源、五州、势力、圣旨、奏折、事件、技能、叛乱”串成一个真正可以连续运行的月度模拟循环。

玩家不需要管理真实地图上的每一座城市。地方问题通过“州级状态 + 奏折”上报到主城区。

一局约30年 = 360个月。

---

## 2. 时间单位

### 月

月是核心模拟单位。

一个月完成一次完整国家结算。

### 季度

每3个月触发季度型统计、税收修正、部分政策结算。

### 年

每12个月：

- 获得年度技能点
- 年度财政结算
- 年度人口变化
- 年度评价记录
- 年度重大事件概率修正

### 30年

360个月后：

- 正常退位
- 生成皇帝历史评价
- 统计30年统治行为

如果提前死亡、政变、全国性叛乱成功等，则提前结束。

---

# 3. 每月完整流程

```text
月初
 ↓
① 时间推进
 ↓
② 州生产
 ↓
③ 国家资源收入
 ↓
④ 国家资源消耗
 ↓
⑤ 势力状态更新
 ↓
⑥ 州状态更新
 ↓
⑦ 技能/政策持续效果
 ↓
⑧ 随机事件判定
 ↓
⑨ 事件生成奏折
 ↓
⑩ 玩家阅读奏折
 ↓
⑪ 玩家做出决策
 ↓
⑫ Action → Effect
 ↓
⑬ 后续事件 / 奏折生成
 ↓
⑭ 叛乱 / 政变判定
 ↓
⑮ 月末统计与历史记录
 ↓
进入下月
```

玩家主要操作集中在第⑩～⑫步。

其他阶段由模拟器自动运行。

---

# 4. ① 时间推进

月份 +1。

更新：

- 皇帝年龄
- 当前年份
- 当前月份
- 技能冷却
- 圣旨持续时间
- 临时Modifier持续时间
- 战争持续时间
- 事件持续时间

皇帝初始年龄建议：30岁。

第360个月结束时：60岁左右退位。

---

# 5. ② 州生产

五州分别生产自己的基础资源。

每州至少计算：

- 粮食
- 财政
- 人口增长
- 治安

基础公式：

```text
实际产出 = 基础产出
         × 人口修正
         × 治安修正
         × 临时Modifier
         × 灾害修正
```

州之间不需要真实地理运输模拟。

中央只关心：

> “这个州本月给朝廷上缴了多少？”

---

# 6. ③ 国家资源收入

州级产出的一部分进入中央国库 / 粮库。

建议默认：

```text
中央财政收入 = 各州财政产出 × 中央征收效率
中央粮食收入 = 各州粮食产出 × 粮税效率
```

中央征收效率受以下因素影响：

- 皇权
- 士族影响
- 豪强影响
- 贪腐
- 地方忠诚
- 集权技能

因此“江南很富”不等于“皇帝真的拿得到钱”。

---

# 7. ④ 国家资源消耗

每月自动计算：

### 军队

```text
军粮消耗 = 军队规模 × 基础军粮消耗
```

### 行政

```text
行政成本 = 基础成本 + 中央直辖成本 + 特殊制度成本
```

### 战争

如果处于战争：

- 额外粮食消耗
- 兵器消耗
- 国库消耗
- 军队损耗

资源不足不会直接 Game Over。

而是产生后果：

```text
军饷不足 → 武将不满
粮食不足 → 民心下降
行政经费不足 → 腐败上升
兵器不足 → 战争能力下降
```

---

# 8. ⑤ 势力状态更新

每月重新计算四大政治集团：

- 士族
- 武将
- 百姓
- 豪强

每个势力至少拥有：

```text
satisfaction
influence
wealth
organization
resentment
fear
```

注意：

**满意度和影响力完全分开。**

例如：

> 士族满意度20，但影响力90。

这是危险状态。

---

# 9. 满意度变化来源

满意度不是每月随机变化，而是由过去行为积累。

来源包括：

- 圣旨
- 技能
- 事件选择
- 资源分配
- 战争
- 灾害
- 税收
- 征兵
- 官职任命
- 其他势力得利

推荐公式：

```text
本月满意度变化
= 政策影响
+ 事件影响
+ 资源影响
+ 环境影响
+ 历史Modifier
```

并设置每月自然回归，防止一次事件永久决定势力态度。

---

# 10. 积怨系统

满意度低不立即叛乱。

当势力长期受到伤害时增加 `resentment`。

例如：

```text
满意度 < 40
→ 每月积怨 +1

满意度 < 25
→ 每月积怨 +2

满意度 > 60
→ 积怨缓慢下降
```

积怨代表：

> “这件事我已经记在心里了。”

这样玩家即使后来提高满意度，也可能需要多年才能消除过去造成的伤害。

---

# 11. ⑥ 州状态更新

每州更新：

- security
- morale
- corruption
- local_loyalty
- rebellion_risk
- faction influence

例如：

```text
豪强影响力高
+ 官员腐败高
+ 中央征收效率低
= 税收流失
```

又例如：

```text
粮食低
+ 民心低
+ 治安低
= 民变风险快速增加
```

---

# 12. ⑦ 技能 / 政策持续效果

检查所有持续中的：

- 技能
- 圣旨
- 制度
- 战争状态
- 灾害
- 临时Buff/Debuff

例如：

### 轻徭薄赋

持续3个月：

```text
百姓满意度 +3/月
中央税收 -15%
```

### 天威如狱

持续6个月：

```text
强制圣旨执行率提高
叛乱风险下降
势力恐惧提高
```

---

# 13. ⑧ 随机事件判定

事件不是完全随机。

采用：

```text
基础概率
× 州状态修正
× 国家状态修正
× 势力状态修正
× 历史Modifier
```

例如旱灾：

```text
基础概率 2%

粮食 < 50 → ×1.5

民心 < 40 → ×1.2

连续三个月高温 → ×2
```

这样玩家能够通过治理降低事件风险，但不能完全控制命运。

---

# 14. 事件产生方式

事件发生后，不直接弹出“事件面板”让玩家看所有信息。

而是转化为：

> **奏折。**

例如：

```text
【河东州·急奏】

臣启陛下：
今岁久旱，河东州粮价暴涨，已有流民聚集。
请陛下速定方略。

[拨粮赈灾]
[暂缓税赋]
[命地方自救]
[严禁流民聚众]
```

玩家做出的选择再进入 Action → Effect。

---

# 15. ⑨ 奏折生成规则

奏折来源：

- 州官
- 武将
- 士族
- 豪强
- 百姓代表
- 钦差
- 战场
- 外交
- 特殊事件

奏折不应该全部是真实信息。

但第一版不做复杂的“真假推理”。

重点是：

> **同一个问题，不同势力会提供不同的解决方案。**

例如旱灾：

### 士族奏折

> 请求免除地方赋税。

### 豪强奏折

> 请求允许民间商人自由调粮。

### 百姓奏折

> 请求开仓赈济。

### 武将奏折

> 请求派兵维持灾区治安。

皇帝必须选择。

---

# 16. ⑩ 玩家决策窗口

这是游戏的核心操作阶段。

玩家可以：

- 批准奏折
- 驳回奏折
- 修改方案
- 发布圣旨
- 使用政策技能
- 调拨资源
- 任命 / 调动人物（后续）
- 暂不处理

原则：

> **不是每个月必须做很多操作。**

平稳月份应该轻松。

危机月份才让玩家连续决策。

---

# 17. ⑪ Action → Effect

玩家点击一个决策后：

```text
Action
 ↓
检查条件
 ↓
计算公式
 ↓
生成Effects
 ↓
修改国家 / 州 / 势力状态
 ↓
记录历史日志
```

例如：

```text
Action:
issue_edict("relief")

Effects:
food -3000
treasury -500
peasants satisfaction +10
rebellion risk -8
```

---

# 18. ⑫ 后续事件

重要决策不是立即结束。

Effect 可以创建后续事件。

例如：

```text
赈灾
 ↓
百姓满意
 ↓
但粮食下降
 ↓
三个月后粮荒
```

或者：

```text
抄没豪强
 ↓
国库增加
 ↓
豪强积怨增加
 ↓
“豪强密谋”
 ↓
资助土匪
 ↓
州治安下降
```

这是游戏产生故事感的主要方式之一。

---

# 19. ⑬ 叛乱判定

叛乱不是单一数值超过阈值就必然发生。

基础模型：

```text
rebellion_score
= dissatisfaction
+ resentment
+ organization
+ local_influence
+ security_penalty
+ event_bonus
- imperial_suppression
- fear
```

### 轻度

`0～39`

正常不满。

### 紧张

`40～59`

开始出现：

- 民变传闻
- 豪强密谋
- 军队欠饷
- 地方抗命

### 危险

`60～79`

可能出现组织化反抗。

### 临界

`80～99`

高概率发生叛乱 / 政变。

### 爆发

`100+`

触发对应势力的重大行动。

---

# 20. 不同势力的“造反”方式

四大势力不能全部变成同一种叛乱。

## 百姓

```text
流民
 ↓
土匪
 ↓
民变
 ↓
农民军
 ↓
州级叛乱
```

## 豪强

```text
抗税
 ↓
拒绝执行圣旨
 ↓
资助土匪
 ↓
地方割据
```

## 士族

```text
舆论反对
 ↓
官员集体抵制
 ↓
地方行政瘫痪
 ↓
逼宫 / 政变
```

## 武将

```text
军队欠饷
 ↓
军心动摇
 ↓
将领抗命
 ↓
兵变
 ↓
拥立 / 政变
```

这会让“亡国”拥有不同故事。

# 21. 平叛

平叛是一个 Action，而不是战斗小游戏。

玩家选择：

- 派兵
- 招安
- 赈灾
- 谈判
- 强行镇压

派兵消耗：

```text
军队
粮食
兵器
国库
```

成功率取决于：

```text
中央军力
+ 将领能力
+ 州治安
+ 皇权
+ 技能
- 叛军组织力
- 地方支持
```

历史记录用于：

# 23. 月度循环的“玩家节奏”

不是每个月都应该同样忙。

推荐三种月份：

### 平稳月

```text
1～2封奏折
少量资源变化
没有重大事件
```

体验：

> “经营国家。”

### 紧张月

```text
3～5封奏折
1个重要事件
多个势力同时提出要求
```

体验：

> “朕该帮谁？”

### 危机月

```text
5+奏折
灾害 / 战争 / 叛乱
资源快速消耗
多个连锁事件
```

体验：

> “救哪一个？另一个怎么办？”

这是本作最爽的时刻。

# 26. V0.4 最重要的设计原则

### 原则一：地方不是地图操作

玩家看到的是州级概况和奏折。

### 原则二：问题通过奏折来到皇帝面前

玩家永远在“处理问题”，而不是点击地图收税。

### 原则三：玩家的选择应该产生后续问题

一个问题解决后，不应该意味着系统恢复原状。

### 原则四：技能改变解决问题的方法

例如：

```text
普通皇帝：没钱 → 加税
仁政皇帝：没钱 → 天下共济
暴政皇帝：没钱 → 强行征税
集权皇帝：没钱 → 钦差查税
强兵皇帝：没钱 → 对外战争
```

### 原则五：失败不是“系统错误”，而是故事

皇帝被武将推翻、被士族逼宫、被农民军攻入京城，都应该成为一段完整的30年历史故事。

# 27. V0.4 验收标准

不做美术、不做完整UI之前，程序模拟器必须能够连续运行至少360个月。

最小验收流程：

1. 初始化皇帝
2. 初始化五州
3. 初始化四大势力
4. 每月资源生产
5. 每月资源消耗
6. 生成事件
7. 生成奏折
8. 玩家 / 测试AI选择行动
9. Action → Effect
10. 状态变化
11. 叛乱判定
12. 平叛
13. 历史日志
14. 连续运行30年
15. 输出最终皇帝评价

如果这条链可以稳定运行，那么游戏核心模拟器就成立了。

# 28. 下一阶段：V0.5

V0.5 不继续增加大量内容，而是做：

> **第一年完整模拟测试。**

目标：让程序连续模拟“登基第一年12个月”，并人工检查：

- 有没有无意义的资源变化
- 玩家是否有足够决策
- 技能是否真的改变玩法
- 势力是否会过快崩溃
- 是否存在无脑最优策略
- 是否能产生有趣的故事

V0.5 的核心不是增加系统，而是回答：

> **“这个游戏到底好不好玩？”**
